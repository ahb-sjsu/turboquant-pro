# Retrieval and storage survey for the console redesign (turboquant-pro)

Source: `origin/master` at 24d49ac, extracted read-only with `git archive` to `scratchpad/m/`. I did not use `C:\source\tqp-master-wt` because it is on branch `bench-outlier-latency`, not master. Nothing in `C:\source\turboquant-pro` was changed. The only git operation was a `git fetch`. Everything here comes from reading the code. I ran nothing.

Workspace abbreviations: OV Overview, QI Queries, RS ReadScope, VS Vector Space, IS Index & Shards, BM Benchmarks, SY System, ST Settings.
Where a value lives today: **ret** = return value, **stats** = a `stats()` or `as_dict()` dict, **art** = an artifact file with its schema name, **none** = nothing exposes it.

---

## 0. What the console can see today (the baseline every "missing" column is measured against)

- **The telemetry registry is small.** `telemetry/metrics.py` holds about 12 metrics: `search.qps`, the latency p50/p95/p99, `search.stage_ms.{encode,scan,rerank}`, `search.rerank_agreement`, `index.compression_ratio`, `index.rows`, `process.cpu_percent` and `process.rss_mb`.
- **One search path is instrumented.** Only `ADCIndex.search` emits a trace (`adc_index.py:696`), using the `turboquant-pro/query-trace` v1 schema. A trace carries stages, `scan_path` (kernel, kernel_pruned, numpy or exact), and the approximate and final top-k of the first query, with rank movement. No other index type calls `telemetry.begin`: not TQEIndex, IVFIndex, ShardedIndex, CompressedHNSW, TurboQuantFAISS, pgvector, cuda_search or distributed.
- **Bug, found by reading only.** `tqp console --index` opens a real index through `cli._open_index_for_search(path, mmap=True)`. `TQEIndex.search` with `mmap=True` goes through `_candidate_search` (the blocked scan), which never calls `ADCIndex.search`. So **a real TQE or sharded index produces no query traces at all**. Only `--demo`, which builds a bare ADCIndex, is live. A sharded index opened without mmap would produce one ADCIndex trace per shard, not one trace per query.
- **Bug, found by reading only.** `console/server.py:104` calls `index.search(q, k=, rerank=, originals=)`. `TQEIndex.search` and `ShardedIndex.search` have no `originals` parameter. So `tqp console --index X --originals O --rerank R` should raise a TypeError on every query, which the workload loop counts in `errors`.
- **Index entity.** `_index_entity` shows `index.stats()` for whatever index is open. That dict is the whole Index & Shards feed today.

These gaps come first. Most of the live Queries and Index workspace depends on instrumenting TQEIndex, IVF and ShardedIndex, not ADCIndex alone.

## Features with no sensible visualization of their own

- **`metrics.py` (check_metric, exact_scores).** A definition, not a state. It surfaces only as the metric chip on every score.
- **`export.py` exporters.** A format transform, so the console needs at most an action with a count.
- **`packed_codes.pack_bits` / `unpack_bits` and `format.pack` / `unpack`.** Byte transforms. Their only visible effect is bytes per row, which belongs to the index view. A byte-layout ribbon is documentation, not telemetry.
- **`ans_codec.ANSCodec`.** Visible only as the "graph compressed" figure in the HNSW memory bar.
- **`nats_worker.main`.** An entrypoint. Its state belongs to the NATS worker liveness row, which needs counters that do not exist yet.
- **`connectors/identity.prefix_block_hashes`.** Hash chains carry no quantity. Show only the profile digest and compatibility status.
- **`distributed.encode_request` / `decode_request` and `encode_response` / `decode_response`.** Wire encoding only.
